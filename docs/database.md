# 数据库设计文档

## 文档作用

本文件用于说明项目数据库的结构、数据关系、约束、索引和迁移约定，帮助开发、测试和运维人员理解数据模型。

数据库的实际结构以迁移脚本和当前线上版本为最终准则；本文件用于补充设计意图和维护规则。

## 维护规则

- 新增、删除或修改表字段时同步更新本文件和数据库迁移脚本。
- 不直接在生产环境手工修改表结构，结构变更必须可追踪、可回滚。
- 字段说明应包含用途、是否必填、默认值、取值范围和敏感性。
- 涉及用户、订单、权限等核心数据的变更，应补充数据迁移和回滚方案。
- 数据库变更发布后，在 `changelog.md` 中记录迁移要求。

## 命名与通用约定

- 表名：待确定，建议使用小写下划线命名。
- 主键：待确定，建议统一使用 UUID 或自增整数。
- 时间字段：建议统一使用 `created_at`、`updated_at`，并明确时区。
- 软删除：如使用，统一说明 `deleted_at` 或状态字段的语义。
- 外键：明确删除行为，例如 `RESTRICT`、`CASCADE` 或置空。
- 敏感字段：密码、Token、身份证号等不得明文存储。
