# API 规则

本文件只记录接口必须遵守的规则。具体接口写在 `docs/api.md`。

路径、参数、请求体和响应模型以 OpenAPI 为准：

- Swagger UI：`/docs`
- ReDoc：`/redoc`
- OpenAPI Schema：`/openapi.json`

## 维护规则

- 新增或修改接口时，同时更新 FastAPI 路由、Pydantic 模型和 `docs/api.md`。
- 规则本身有变化时，更新本文件。
- 所有接口设置清晰的 `summary`、`description`、响应模型和状态码。
- 破坏性变更必须说明影响范围、迁移方式和兼容期限。
- 文档示例不得包含真实账号、Token、密钥或生产数据。
- 发布接口变更时，在 `docs/changelog.md` 中记录。

## REST

- 路径以 `/api/v1` 开头，资源用复数名词，例如 `/api/v1/users`。路径里不写动词。
- 多个单词用连字符，例如 `/api/v1/interview-sessions`。
- 用 HTTP 方法表示操作：`GET` 查询，`POST` 创建，`PUT` 整体替换，`PATCH` 部分更新，`DELETE` 删除。
- 集合用 `/api/v1/users`，单个资源用 `/api/v1/users/{id}`。从属资源挂在父资源下，例如 `/api/v1/users/{id}/sessions`。
- 过滤、排序和分页放在查询字符串里，不放进路径。
- `GET`、`PUT`、`DELETE` 保持幂等。同一请求重复执行，结果与执行一次相同。
- 创建成功返回 `201`，删除成功返回 `204`。查询和更新成功返回 `200`。
- 结果以 HTTP 状态码为准。成功时响应体直接是资源本身，不使用 `code`、`message`、`data` 外壳。`204` 不带响应体。
- 失败时响应体为 `{"detail": "错误说明"}`。密码哈希、验证码不得出现在响应里。
- 当前版本是 `v1`，放在路径前缀 `/api/v1`。
- 删除或重命名字段前，先标记废弃并保留兼容期。
- 认证使用 `Authorization: Bearer <access_token>`。

## 通用响应

默认数据格式为 `application/json`。时间使用 ISO 8601 UTC，例如 `2026-10-12T08:00:00Z`。

创建成功直接返回资源：

```json
{
  "id": 1,
  "email": "user@example.com"
}
```

失败时返回：

```json
{
  "detail": "错误说明"
}
```

## 常用状态码

| 状态码 | 含义 | 使用场景 |
| --- | --- | --- |
| 200 | 成功 | 查询或更新成功 |
| 201 | 已创建 | 创建资源成功 |
| 204 | 无内容 | 删除成功 |
| 400 | 请求错误 | 参数格式或业务参数不合法 |
| 401 | 未认证 | Token 缺失或无效 |
| 403 | 无权限 | 已认证但无访问权限 |
| 404 | 不存在 | 目标资源不存在 |
| 409 | 冲突 | 重复创建或状态冲突 |
| 422 | 参数校验失败 | FastAPI/Pydantic 校验失败 |
| 429 | 请求过多 | 发送验证码过于频繁 |
| 500 | 服务端错误 | 未预期的服务端异常 |
