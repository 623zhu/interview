# 数据库设计规则

本文件只记录建表和改表时必须遵守的规则。按这些规则完成模型和迁移后，把表设计写入 `docs/database.md`。

实际表结构以 Alembic 迁移脚本为准。

## 维护规则

- 创建或修改表时，先按本文件的规则实现 ORM 模型和 Alembic 迁移，再把表、字段、关系、索引和迁移记录写入 `docs/database.md`。
- 规则本身有变化时，更新本文件。
- 不直接在生产环境手工修改表结构。结构变更必须可追踪、可回滚。
- 字段说明写明用途、是否必填、默认值、取值范围和敏感性。
- 涉及用户、权限等核心数据的变更，补充数据迁移和回滚方案。
- 数据库变更发布后，在 `docs/changelog.md` 中记录迁移要求。

## 数据库基础信息

| 项目 | 内容 |
| --- | --- |
| 数据库类型 | MySQL |
| 数据库版本 | 8.4 |
| 存储引擎 | InnoDB |
| ORM / 数据访问层 | SQLAlchemy 2.0，异步驱动 asyncmy |
| 迁移工具 | Alembic |
| 字符集与排序规则 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 时区 | 容器时区 `Asia/Shanghai`；时间列由应用写入 UTC |

## 命名与通用约定

- 表名、列名、索引名使用小写加下划线。表名用复数，例如 `users`。
- 主键列统一叫 `id`，类型 `BIGINT UNSIGNED`，`AUTO_INCREMENT`。
- 每张业务表都有 `created_at` 和 `updated_at`，类型 `DATETIME(6)`，非空。应用写入 UTC 时间，不使用 `TIMESTAMP`，避免会话时区改变读出的值。
- 字符串列必须写明长度，短文本用 `VARCHAR`，不拿 `TEXT` 代替。
- 状态和枚举用 `VARCHAR`，合法取值写在对应表的字段说明里，不用 MySQL `ENUM`。
- 布尔值用 `TINYINT(1)`，列名以 `is_` 或 `has_` 开头。
- 金额用 `DECIMAL`，不用浮点类型。
- 默认不做软删除。某张表需要保留已删除记录时，再增加可空的 `deleted_at`，查询默认加上 `deleted_at IS NULL`。
- 密码只存哈希。验证码、发送频率限制和短期令牌放 Redis，并设置过期时间，不建表。

## 约束

- 业务上必填的列设为 `NOT NULL`。可空列必须在字段说明里写明为空时的含义。
- 账号、邮箱这类不能重复的列建数据库唯一约束，不依赖应用层先查再插。
- 库默认排序规则不区分大小写。需要区分大小写的列单独指定排序规则。`email` 使用 `utf8mb4_0900_as_cs`，因此邮箱唯一约束区分大小写。
- 外键默认 `ON DELETE RESTRICT`、`ON UPDATE RESTRICT`。从表记录的生命周期完全依附主表时，才使用 `ON DELETE CASCADE`。
- 外键列要有索引。MySQL 会为外键自动建索引；联合查询需要别的列顺序时再另建索引。
- 索引按查询建立，不为尚未出现的查询预留索引。

约束和索引命名：

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 唯一约束 | `uq_<表>_<列>` | `uq_users_email` |
| 普通索引 | `ix_<表>_<列>` | `ix_users_created_at` |
| 外键 | `fk_<表>_<列>_<引用表>` | `fk_orders_user_id_users` |
